# DentMarket — Production preview / дизайн, не production-приёмка

Основание: явный запрос владельца 16.09.2026 из pasted-text.txt. Четыре исходных
изображения утверждены как визуальное направление. Новые макеты и точные токены
требуют отдельного утверждения. Код приложений, БД, зависимости и engineering
чекбоксы не изменяются. Материалы изолированы в этой папке.

## Набор для одного прохода — организация 21.09.2026

Начните с [review/index.html](review/index.html): четыре PNG направления,
затем 78 HTML через «Следующий», затем два дополнительных AI-концепта.
[Чеклист](review/CHECKLIST.md) содержит каждый ID один раз, все статусы —
«Ожидает утверждения». Решения сообщаются владельцем отдельно; генератор
не утверждает элементы и не сохраняет пользовательские отметки в generated files.

Реальные папки: публичные страницы (3), покупатель (14), поставщик (11),
оператор (19), авторизация (6), модальные окна/панели (13), компоненты (4),
системные состояния (6), юридические страницы (2). Сумма 78. Объединённый
components-overlays учитывается только в компонентах; из панелей есть ссылка.
00-исходное-направление и 10-дополнительные-концепты содержат соответственно
четыре и два побайтных PNG-дубликата для просмотра, вне счётчика 78.
Диагностические screens/evidence PNG не включены.

Единственные исходники упаковки — pages.js, существующие rendered/*.html,
originals/ и concepts/. organize-review.mjs генерирует review/ целиком:

```powershell
node actual_docs/ui-ux/references/production-preview-2026-09-16/organize-review.mjs
node actual_docs/ui-ux/references/production-preview-2026-09-16/organize-review.mjs --check
```

При будущем изменении самих макетов сначала применяется прежний validate.mjs,
который обновляет rendered, затем этот генератор. В текущей организационной
задаче старые generators/evidence и snapshots не перезаписывались. --check
ничего не пишет: сверяет coverage, результаты генерации и ссылки/assets.
Повторная генерация не зависит от времени; неизвестные файлы не удаляются,
устаревшие пути из предыдущего manifest требуют отдельного решения.

Откройте review/index.html обычным файловым способом в браузере; сервер для
статичных HTML не нужен. На каждом экране есть прежняя ссылка на интерактивный
прототип. Исходные index/preview/viewer/rendered, PNG и шрифты сохранены.
Техническая упаковка не меняет PROPOSED/acceptance статусы и не начинает редизайн.

## Текущий результат

Созданы 78 HTML-поверхностей на 69 шаблонах и два AI-концепта. Полноразмерные
статичные копии находятся в `rendered/`; исходные PNG — в `originals/`.
Новые макеты имеют статус PROPOSED. Полная визуальная приёмка и точный PNG-экспорт
не завершены; ограничения и проверенные действия перечислены в отчёте.

Самостоятельный read-only сервер: `http://127.0.0.1:4327/`.
Запуск из корня репозитория:

```powershell
node actual_docs/ui-ux/references/production-preview-2026-09-16/serve.mjs
```

Он слушает только loopback, не импортирует приложения, не подключается к API/БД
и не принимает записи. Не останавливайте основной dev-server ради просмотра.
Для просмотра без сервера откройте HTML-файлы обычным локальным файловым способом.

## Граница и проверки

Git baseline: codex/frontend-pilot-composition, HEAD
3d644963ed72f99a100e180db2d373bc5abeaef9, dirty дерево, параллельный AUD-FIX-05.
Оба UI standards уже изменены: не перезаписываются. Это handoff к существующим
стандартам, не новый продуктовый backlog. Исходные маршруты и статусы снимок,
а не свежая функциональная сертификация.

DoD: инвентаризация actual/target/conditional поверхностей; единая оболочка;
читаемые desktop/mobile макеты и атлас компонентов; контрольный набор до массовой
генерации; визуальная проверка, ссылки и отсутствие переполнения в локальном
прототипе; явные approval gaps. Browser только isolated static preview, без API.
Нет root builds/tests, npm install, DB, external sends, commit/push, subagents.

Бюджет: дизайн-сессия до120мин; один imagegen до10мин; browser probe до2мин;
проверочная серия до30мин; диагностика одного блокера15мин, максимум3попытки.
Не создавать новые варианты без конкретного дефекта. При неполноте сохранить
checkpoint, не объявлять полный комплект принятым.

Практики: прочитаны Agency UI Designer/UX Architect (foundations, reuse, states,
handoff), Taste Redesign (типографика/ритм в пределах эталонов), imagegen
(style-reference, invariants), Playwright (практики проверки прототипа). Фактический
браузерный контроль — in-app Chromium через CUA/Playwright API, CLI не установлен.
Упоминаемый Agency
`ai/agents/architect.md` не найден одним целевым поиском: используется доступный
основной checklist. Dark-mode/анимации из внешних примеров не расширяют scope.

## Статусы

- `OWNER_DIRECTION` — только исходное визуальное направление владельца.
- `PROPOSED` — новые tokens/layout/copy, не утверждены автоматически.
- `CREATED` / `VISUALLY_REVIEWED` — статусы артефакта.
- `IMPLEMENTED` / `RUNTIME_TESTED` — не присваиваются созданным референсам.

Макеты используют синтетические данные; никакие изображения не доказывают
оплату, ЭЦП, доставку, tenant isolation или готовность к production.
