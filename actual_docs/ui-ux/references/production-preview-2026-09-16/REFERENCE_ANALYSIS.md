# Детальный разбор четырёх оригиналов

16.09.2026. Все четыре файла открыты и визуально изучены до генерации.
Источник: предоставленные владельцем PNG, не скриншоты работающего приложения.
Точный размер/hash фиксируется `source-manifest.json`. Ниже координаты/размеры
определены визуально приблизительно, если прямо не указано измерение.

## 1. Общая грамматика — утверждённое направление

Светлая почти белая тёплая основа, графитовый текст, глубокий зелёный primary,
тонкая светло-серая сетка. Не «премиальность через декор», а крупный читаемый
заголовок, открытый контент, понятные числа и честные состояния. Успех зелёный,
warning янтарный, blocking error красный с текстом. Акцент не заливает весь экран.

Контент начинается около x46 и заканчивается x1490 в1536px canvas. Верхняя
навигация — горизонтальная, без постоянного меню слева. Фотографии товаров
нейтральные студийные, без декоративной обводки; они помогают опознать товар.
Границы около1px, radius около4–6px, почти нет теней у основных поверхностей.
Тени допустимы для действительно всплывающего слоя, не для каждой карточки.

Типографика: большой H1 примерно40–44px в трёх деталях, каталог примерно36px;
body16–18px, meta13–14px, сильные суммы24–32px. Эти числа НЕ извлечённые CSS.
Шрифт PNG точно не установлен. В actual code всех4layout используется Manrope
через next/font/google, subsets Cyrillic/Latin. Поэтому Manrope — существующая
repo-основа для прототипа, а не доказательство семейства растрового оригинала.
Технический mono документирован для IDs, не обязателен для всех денежных сумм;
для денег нужны tabular figures и выравнивание по правому краю.

## 2. R01 — заказ поставщика, 19_23_11

Композиция: header≈74px; заголовок+номер слева, статус рядом; buyer/date ниже,
demo label справа. Затем горизонтальные4этапа, большая таблица, итоговая полоса,
actions справа и два блока «Документы/История». Это full-width рабочий экран,
не карточный dashboard. Номер и состояние важнее декоративной статистики.

Таблица: товар/packshot, цена за упаковку, заказано, подтверждаем, сумма.
Большая высота строки оправдана полем причины частичного подтверждения.
Уменьшение3→2 выделено text+warning. Итог до63400, после55950, разница−7450;
арифметика верна:37800+14900+3250=55950. История и документы — соседние контексты.

Заимствуем: историю решения, разделение requested/accepted, причину рядом,
понятный preview итогов и primary «Подтвердить частично».
Не копируем без проверки: шаги timeline как точные API enums; кнопку «Отмена»
без уточнения, отменяет ли она редактирование или весь заказ; обязательность
текстовой причины должна соответствовать конкретной операции. Черновик решения
ещё не состоявшееся подтверждение. Это отдельный supplier order: не смешивать
его с одной общей суммой multi-supplier checkout из R02.

## 3. R02 — корзина/reprice, 19_23_04

Header соответствует R03; H1≈44px и строка3позиции/3поставщика. Полноширинный
warning над двухколоночной областью: таблица≈1048px, gap≈14px, summary≈382px.
Итог справа — контент страницы, не глобальная боковая навигация.

Цена композита17900→18900 за упаковку, quantity2 даёт+2000. Файлы: заказано3,
остаток8→2; строка не уменьшается молча. Сумма63400=37800+22350+3250,
предыдущая61400, разница2000. Error рядом со строкой и summary объясняет
недоступность checkout. Перчатки остаются нейтральной незатронутой строкой.

Заимствуем: struck old/new amounts, before/after stock, локальную причину
блокировки, разделение акцепта и checkout. Дополняем: явный Save/Cancel количества
и Delete confirmation из принятого AUD-FIX-04. Stepper сам по себе НЕ разрешает
autosave. «Принять изменения» не снимает недостаточный остаток. Успешная запись
и успешная серверная revalidation — разные состояния. Нужны409/network/empty.

## 4. R03 — товар и предложения, 19_22_51

Композиция: breadcrumbs, большой canonical title, объяснение сравнения одинаковой
упаковки. Фото≈478×230, справа характеристики; ниже открытая таблица предложений
и tabs характеристик/описания. Упаковка4г и единица закупки«упаковка» явные.

Три supplier offers, а не три цены абстрактного canonical товара. Price,stock,
updated,quantity иCTA находятся в одной строке. Stale offer отмечен янтарным,
нет актуального остатка, buy action disabled с причиной. Первая строка зелёная.

Заимствуем: source/supplier рядом с условиями, единицу закупки, свежесть,
информационное отделение свойств товара от коммерческих условий.
Уточнение: зелёную строку обозначать как «Выбрано» только после выбора; не
выдавать её за лучший/проверенный вариант без ranking/trust основания. У свежих
предложений более низкая цена не единственный критерий. Нужны image fallback,
нет предложений, варианты упаковок и mobile cards с теми же данными.

## 5. R04 — каталог, 19_22_42

Более тёплый фон, открытая сетка3колонки, локальные фильтры≈270px слева и
разделитель. Header контент ниже из-за служебной надписи «B · Quiet Editorial»;
поиск шире, отсутствует «Ещё». Карточки не окружены тяжёлыми тенями: фото сверху,
updated→название→pack→price→supplier→stock→compare/quantity/add.

Заимствуем: короткий путь от поиска к покупке, открытые товарные колонки,
фильтры как рабочий инструмент и выравнивание карточек. Локальные категории
не являются глобальным sidebar. Новое решение владельца разрешает их слева.
Не копируем служебную подписьB, несогласованные счётчики и demo taxonomy. По
растровому снимку нельзя доказать, что фильтр«Терапия» правильно соответствует
каждой карточке или как считаются фасеты. Пагинация/пустая выдача отсутствуют
в crop, их нужно показать отдельно, а не объявить ненужными.

## 7. Отсутствующее и риски буквального копирования

Все PNG desktop-only; отсутствуют полноценные login/registration, operator,
documents archive, long forms, open dropdown/dialog, focus trap, mobile/tablet,
loading/empty/error/403/session expired, invalid files и concurrent changes.
Header scroll не доказан. Маленькие minus/plus могут иметь недостаточный touch
target; proposed44px минимум для touch, без увеличения каждой desktop строки.
Tooltip не заменяет label/критическую инструкцию. Disabled без причины недопустим.
Генераторные gradient/noise на CTA — не обязательная текстура CSS.

## 8. Решения, не вытекающие из картинки

Оригиналы утверждают направление, но не сроки договора, способ ЭЦП, тариф,
метрику trust, статус оплаты или гарантии доставки. Product §9/actual schemas
сохраняют приоритет. Manual payment CORE-02 ещё proposal: только концепт с
соответствующей маркировкой. Квитанция/бухгалтерская отметка не равны оплате.
Расположение compact auth header отдельно запрошено у владельца до создания
отличающейся оболочки. Остальные роли используют полный общий header.
